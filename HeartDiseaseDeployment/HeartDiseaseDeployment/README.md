# Heart Disease Prediction — End-to-End ML Deployment

A machine learning web application that predicts whether a patient is at risk
of heart disease based on clinical parameters. Includes a trained
classification model, a Flask REST API, and a web interface — deployed live
on Render.

## 📊 Dataset

[Heart Disease Dataset — Kaggle (johnsmith88)](https://www.kaggle.com/datasets/johnsmith88/heart-disease-dataset)

14 columns: `age, sex, cp, trestbps, chol, fbs, restecg, thalach, exang, oldpeak, slope, ca, thal, target`

> **Note:** `heart.csv` in this repo was generated by `generate_sample_data.py` so the pipeline could be built and tested without internet access. **Download the real dataset from Kaggle and replace `heart.csv` before final training/submission**, then re-run `train_model.py`.

## ⚙️ How It Works

1. **`train_model.py`** — loads `heart.csv`, checks for missing values, splits data 80/20, trains a `RandomForestClassifier`, prints accuracy, and saves the model as `model.pkl`.
2. **`app.py`** — loads `model.pkl` and serves:
   - `GET /` → the web interface (fill a form, click **Predict Risk**)
   - `POST /predict` → REST API, accepts JSON, returns JSON

### Example API Request

```bash
curl -X POST https://<YOUR-RENDER-URL>/predict \
  -H "Content-Type: application/json" \
  -d '{
    "age": 63, "sex": 1, "cp": 3, "trestbps": 145, "chol": 233,
    "fbs": 1, "restecg": 0, "thalach": 150, "exang": 0,
    "oldpeak": 2.3, "slope": 0, "ca": 0, "thal": 1
  }'
```

### Example Response

```json
{
  "prediction": "Heart Disease Detected",
  "confidence": 87.4
}
```

## 💻 Run Locally

```bash
# 1. Clone the repo
git clone https://github.com/<your-username>/HeartDiseaseDeployment.git
cd HeartDiseaseDeployment

# 2. Install dependencies
pip install -r requirements.txt

# 3. (Optional) regenerate sample data, or place the real heart.csv here
python generate_sample_data.py

# 4. Train the model
python train_model.py

# 5. Run the app
python app.py
```

Then open `http://127.0.0.1:5000` in your browser for the web interface.

## ☁️ Deployment on Render

1. **Push this project to a public GitHub repository.**
   ```bash
   git init
   git add .
   git commit -m "Initial commit - Heart Disease Prediction App"
   git branch -M main
   git remote add origin https://github.com/<your-username>/HeartDiseaseDeployment.git
   git push -u origin main
   ```

2. **Create a Render account** at [render.com](https://render.com) and sign in with GitHub.

3. **New → Web Service** → select your `HeartDiseaseDeployment` repository.

4. Configure the service:
   - **Environment:** Python 3
   - **Build Command:** `pip install -r requirements.txt`
   - **Start Command:** `gunicorn app:app`
   - **Instance Type:** Free (or any plan)

5. Click **Create Web Service**. Render will build and deploy automatically. Once live, you'll get a URL like:
   `https://heartdiseasedeployment.onrender.com`

6. **Paste that URL** into the [Live Deployment](#-live-deployment) section at the top of this README, and also submit it in the Google Form.

7. Keep the service active and the GitHub repo public during evaluation.

## 🧪 Model Performance & Conclusion

The Random Forest classifier was trained on an 80/20 train-test split and evaluated using accuracy score (see console output of `train_model.py` for the exact figure on your dataset — the sample data run achieved ~87% accuracy). During deployment, the main challenges were correctly serializing the model and its expected column order so predictions stay consistent between training and serving, and making sure the free-tier Render service handles the model loading correctly on cold start. This project highlights why MLOps matters in real projects: a model is only useful once it is reliably packaged, version-controlled, and served through an accessible API — turning a one-off notebook experiment into a dependable, reproducible service that other systems (or a hospital's own software) can actually call.
